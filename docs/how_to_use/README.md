# 머니로드·머니게이트 개발 기능 운영자 매뉴얼

> 문서 기준일: 2026-07-31
> 문서 대상: 머니로드 앱 운영자, 관리자 계정 사용자, 고객 지원 담당자, 배포·장애 대응 담당자
> 기준 기능: RFC 0001~0008, 별도 RFC 0009 브랜치, RFC 0010 회사 사이트를 합친 통합 배포본

---

## 0. 이 문서를 읽기 전에

### 0.1 문서 목적

이 문서는 현재 개발된 기능을 운영자가 실제로 사용할 수 있도록 다음 내용을 한곳에 정리한다.

- 일반 사용자와 비로그인 사용자가 이용할 수 있는 범위
- 관리자만 사용할 수 있는 뉴스·시그널·공지·토론 운영 기능
- 토론 메시지 가림·삭제, 회원 음소거·차단 절차
- 사진·파일 첨부, 열기, 저장 절차와 제한
- 관심 종목, 가격 알림, 푸시 알림, 문의 접수 운영 방식
- 머니게이트 회사 사이트의 콘텐츠 수정·검수·배포 절차
- 운영 중 자주 발생할 수 있는 오류와 확인 순서
- 현재 화면만 있고 실제 운영 기능으로 연결되지 않은 항목

### 0.2 브랜치 통합 전제

이 매뉴얼은 최종적으로 다음 두 브랜치가 함께 반영된 상태를 기준으로 작성했다.

| 구분 | 브랜치 | 주요 범위 |
|---|---|---|
| RFC 0009 | `feat/rfc-0009-guest-access-onboarding` | 비로그인 접근 정책, 로그인 후 원래 화면 복귀, 신규 회원 온보딩과 관심 종목 DB 저장 |
| RFC 0010 | `feat/rfc-0010-company-website-redesign` | 머니게이트 회사 사이트 개편과 이 운영자 매뉴얼 |

현재 RFC 0010 브랜치만 단독으로 실행하면 RFC 0009의 계정 기반 온보딩·비로그인 접근 변경은 포함되지 않을 수 있다. 운영 배포 전에는 두 변경이 모두 병합됐는지 반드시 확인한다.

### 0.3 기능 상태 표기

| 상태 | 의미 |
|---|---|
| 운영 가능 | 화면, 서버 API, DB 저장이 연결된 기능 |
| 관리자 전용 | `user.role = admin` 계정만 사용할 수 있는 기능 |
| 공개 | 로그인하지 않아도 볼 수 있는 기능 |
| 로그인 필요 | 로그인 세션이 있어야 사용할 수 있는 기능 |
| 준비 중 | 화면 진입 안내만 있거나 로컬 화면 상태만 있고 서버 저장·업무 처리가 없는 기능 |

### 0.4 관리자 권한 원칙

- 앱 안에는 일반 계정을 관리자 계정으로 승격하는 화면이 없다.
- 관리자 계정은 승인된 계정 관리 절차로만 부여해야 한다.
- 관리자 버튼을 화면에서 숨기는 것만으로 권한을 판단하지 않는다.
- 뉴스, 시그널, 공지, 토론방, 메시지 모더레이션, 회원 제재는 서버의 관리자 권한 검사도 통과해야 한다.
- 관리자 권한을 변경한 뒤에는 기존 세션을 종료하고 다시 로그인해 권한이 반영됐는지 확인한다.

### 1.2 비로그인 토론방 동작

비로그인 사용자가 토론방 카드를 누르면 다음 정보까지만 볼 수 있다.

- 방 이름과 설명
- 연결 종목
- 고정 주제와 방 메타 정보
- 메시지 영역을 가리는 로그인 안내

실제 메시지 API는 호출하지 않으며 메시지, 답글, 이미지, 파일 내용은 내려받지 않는다. 로그인 안내를 누르면 로그인 화면으로 이동하고, 로그인에 성공하면 같은 토론방과 기존 위치로 돌아온다.

### 1.3 보호 기능을 누른 뒤 로그인한 경우

- 로그인 전에 누른 화면 주소가 유효하면 로그인 성공 후 그 화면으로 돌아간다.
- 돌아갈 화면이 없거나 허용하지 않는 주소이면 기존 팀장님 흐름대로 마이페이지로 이동한다.
- 로그인 전에 누른 변경 동작 자체는 자동 재실행하지 않는다.
  - 예: 비로그인 상태에서 관심 종목 추가를 눌렀다면 로그인 후 종목 상세로 돌아오지만, 관심 종목 추가 버튼은 사용자가 다시 눌러야 한다.
- 외부 주소나 잘못된 주소를 로그인 복귀 경로로 사용하지 않는다.

## 2. 로그인·회원가입·온보딩 운영

### 2.1 앱 시작 순서

앱을 실행하면 항상 공개 홈 화면이 먼저 열린다.

1. 앱 실행
2. 홈 화면 표시
3. 사용자가 로그인 필수 기능을 선택
4. 로그인 또는 회원가입 화면 표시

신규 가입자에게 온보딩을 보여주기 위해 앱 시작부터 온보딩을 강제로 띄우지 않는다.

### 2.2 로그인

현재 실제 입력 흐름은 다음과 같다.

- 이메일 또는 아이디
- 비밀번호
- 기존 계정 로그인

입력 제한은 다음과 같다.

| 항목 | 제한 |
|---|---|
| 아이디 | 3~30자 |
| 아이디 허용 문자 | 영문, 숫자, `_`, `.` |
| 비밀번호 | 8자 이상 |

소셜 로그인용 정의가 코드에 있더라도 현재 사용자 화면에서 활성화되지 않은 버튼은 운영 기능으로 안내하지 않는다.

### 2.3 신규 회원가입

신규 회원가입이 성공하면 자동 로그인된 상태로 온보딩을 시작한다.

정상 진행 순서:

1. 온보딩 소개
2. 관심 종목 선택
3. 받고 싶은 시그널 종류 선택 화면
4. 준비 완료
5. 관심 종목과 온보딩 완료 상태 저장
6. 홈 이동

#### 관심 종목 정상 완료

- 정상적인 `다음` 진행은 실제 종목을 최소 3개 선택해야 한다.
- 화면에 보이는 임시 종목이 아니라 종목 마스터에 존재하는 실제 종목만 저장한다.
- 관심 종목 저장과 온보딩 완료 저장은 하나의 처리 단위로 실행한다.
- 일부만 저장된 상태를 완료로 처리하지 않는다.

#### 건너뛰기

- 소개 화면의 `건너뛰기`는 정상적인 완료 방식이다.
- 관심 종목 0개로 저장한다.
- 시그널 알림 선택도 없는 상태로 처리한다.
- 온보딩 완료 상태를 저장하고 홈으로 이동한다.
- 관심 종목을 억지로 3개 고르게 하지 않는다.
- 사용자는 나중에 로그인 후 `관심 종목 관리`에서 직접 추가할 수 있다.

#### 시그널 종류 선택 화면

- UI는 유지한다.
- 현재 단계에서는 선택값을 DB나 알림 설정에 반영하지 않는다.
- 운영자는 사용자가 이 단계에서 무엇을 선택했더라도 실제 알림 설정이 변경됐다고 안내하면 안 된다.
- 실제 알림 종류는 로그인 후 마이페이지의 `시그널 알림 설정`에서 관리한다.

#### 온보딩 도중 앱 종료

- 완료 전에 고른 값은 임시 선택값이다.
- 앱을 종료하면 중간 선택은 저장하지 않는다.
- 다음에 로그인 필수 기능을 이용할 때 온보딩을 처음부터 다시 시작한다.
- 기존 가입자는 DB 마이그레이션에서 온보딩 완료 사용자로 처리하므로 온보딩을 다시 띄우지 않는다.

### 2.4 프로필

`마이 > 프로필`에서 다음 작업을 할 수 있다.

- 표시 이름 변경
- 이메일 확인
- 로그아웃
- 계정 삭제

표시 이름은 최대 30자다. 이메일은 프로필 화면에서 직접 수정하지 않는다.

### 2.5 로그아웃

1. `마이` 화면 아래의 `로그아웃` 선택
2. 확인 창에서 `로그아웃` 선택
3. 현재 기기의 푸시 토큰 등록 해제를 최선 노력 방식으로 요청
4. 세션 종료
5. 공개 홈으로 이동

푸시 토큰 해제 실패가 로그아웃 자체를 막지는 않는다.

### 2.6 계정 삭제

계정 삭제는 되돌릴 수 없는 작업이다.

1. `마이 > 프로필 > 계정삭제`
2. 경고 문구 확인
3. 최종 삭제 확인

계정과 관련된 관심 종목, 알림 설정, 세션 정보 등 연결 데이터가 함께 삭제된다. 단순 로그아웃 요청을 계정 삭제로 처리하지 않도록 고객에게 다시 확인한다.

## 3. 홈·시장 지수

### 3.1 홈 구성

홈은 비로그인 사용자도 볼 수 있다. 주요 구성은 다음과 같다.

- 국내외 주요 지수
- 내 관심 종목
- 오늘의 시그널 미리보기
- 주요 뉴스 미리보기

### 3.2 비로그인 홈

- 지수, 공개 시그널 미리보기, 공개 뉴스 미리보기는 표시한다.
- 관심 종목 영역은 로그인 안내를 표시한다.
- 보호 기능을 누르면 로그인 화면으로 이동한다.

### 3.3 로그인 홈

- 관심 종목이 있으면 해당 종목의 시세를 표시한다.
- 관심 종목이 없으면 추가 안내를 표시한다.
- 홈의 시그널은 전체 시그널 화면으로 들어가기 전 제한된 미리보기다.
- 뉴스 카드를 누르면 뉴스 상세를 연다.

### 3.4 시세가 보이지 않을 때

다음 순서로 확인한다.

1. 실시간 서비스가 실행 중인지 확인
2. 실시간 서비스와 API 서버의 `STREAM_TOKEN_SECRET`이 같은지 확인
3. 종목 코드가 종목 마스터에 존재하는지 확인
4. 장 운영 시간 또는 데이터 제공 가능 시간인지 확인
5. 실시간 서비스 로그에서 KIS 연결과 구독 상태 확인

장 마감이나 실시간 틱 미수신 시 화면은 기존 데이터 또는 연결 대기 문구를 표시할 수 있다.

## 4. 종목 검색·종목 상세·관심 종목

### 4.1 종목 검색

종목 검색은 공개 기능이다.

- 종목명 검색
- 종목 코드 검색
- 업종명 검색
- 최근 검색 모양의 예시 칩 표시
- `실시간 인기` 모양의 예시 목록 표시

현재 검색 화면은 서버의 `stock.search` API가 아니라 앱에 포함된 `stocks` 데이터 배열을 검색한다. `최근 검색`, `전체 삭제`, `실시간 인기`, 기준 시각도 실제 사용자 기록이나 실시간 순위에 연결되지 않은 예시 UI다. 운영자는 다음 항목을 실제 기능으로 안내하면 안 된다.

- 사용자별 최근 검색 저장
- 최근 검색 전체 삭제
- 실제 검색량 기반 실시간 인기 순위
- 서버 종목 마스터 전체를 대상으로 한 통합 검색

실시간 시세와 차트 연결은 별도 실시간 서비스가 담당한다. 검색 대상 종목 메타데이터와 실시간 가격 연결을 같은 기능으로 오인하지 않는다.

### 4.2 종목 상세

종목 상세의 공개 범위:

- 현재가
- 전일 대비 등락과 등락률
- 가격·거래량 차트
- 기본 종목 정보
- 차트 기간: `1일`, `3개월`, `1년`, `3년`

로그인이 필요한 동작:

- 관심 종목 등록·해제
- 가격 알림 등록
- 로그인 전용 시그널 전체 확인
- 관심 종목 기반 개인화 영역

관련 뉴스와 토론방이 없는 경우 빈 상태 안내가 표시되는 것이 정상이다.

### 4.3 관심 종목 등록

1. 종목 상세의 별 아이콘 선택
2. 등록 확인
3. 관심 종목 목록 갱신

관심 종목 해제도 확인 창을 거친다.

관심 종목은 다음 기능의 기준이 된다.

- 홈의 내 관심 종목
- 뉴스의 관심 종목 탭
- 토론의 관심 종목 탭
- 관심 종목 뉴스·공시 푸시 대상
- 관심 종목 시그널 푸시 대상

현재 관심 종목 등록 개수에 별도의 앱 제한은 없다.

### 4.4 관심 종목 관리

`마이 > 관심 종목 관리`에서 등록 목록을 확인하고 삭제할 수 있다. 목록에서 삭제한 종목은 이후 관심 종목 기반 뉴스·시그널 알림 대상에서도 제외된다.

## 5. 뉴스 운영

### 5.1 뉴스 탭

뉴스 탭은 다음 카테고리를 제공한다.

- 관심 종목
- 전체
- 시장
- 산업
- 기업
- 해외
- 정책

`관심 종목` 탭은 로그인이 필요하다. 나머지 일반 뉴스와 카테고리 뉴스는 공개한다.

### 5.2 뉴스 표시 규칙

- 수동으로 작성한 기사는 `머니로드 독점`으로 표시한다.
- 자동 수집 기사는 `머니로드 요약`으로 표시한다.
- 연결 종목이 있으면 뉴스 상세에 종목 패널을 표시한다.
- 실시간 시세가 있으면 종목 패널에 현재가와 등락을 표시한다.
- 실시간 시세가 아직 없으면 종목 패널을 유지하고 준비 문구를 표시한다.
- 원문 URL이 있으면 `원문 기사 보기`를 활성화한다.
- 원문 URL이 없으면 버튼을 비활성화한다.
- 썸네일이 없으면 머니로드 기본 썸네일을 표시한다.

### 5.3 관리자 뉴스 작성

진입:

1. 관리자 계정으로 로그인
2. `뉴스` 탭 이동
3. 관리자 작성 버튼 선택
4. `새 뉴스` 화면 작성

입력 항목:

| 항목 | 필수 | 제한·동작 |
|---|---:|---|
| 카테고리 | 필수 | 하나 이상 다중 선택 |
| 최상단 고정 | 선택 | 선택한 카테고리 상단에 표시 |
| 제목 | 필수 | 최대 120자 |
| 내용 | 필수 | 최대 4,000자 |
| 원문 링크 | 선택 | 올바른 URL 형식 |
| 썸네일 | 선택 | 1장, 원본 최대 10MB |

작성 화면의 카테고리 저장값과 표시명:

| 화면 | 저장값 |
|---|---|
| 시장 | `market` |
| 산업 | `sector` |
| 기업 | `company` |
| 해외 | `global` |
| 정책 | `other` |

저장 절차:

1. 필수 항목 입력
2. 필요하면 썸네일 선택
3. `저장` 선택
4. 로컬 썸네일이 있으면 먼저 업로드
5. 업로드 성공 후 기사 생성
6. 뉴스 목록으로 이동하고 피드 갱신

썸네일 업로드에 실패하면 기사도 저장하지 않는다. 썸네일 없이 저장하려면 선택한 사진을 명시적으로 해제한 뒤 다시 저장한다.

작성 취소를 누르면 작성 내용이 저장되지 않는다는 확인 창이 표시된다.

### 5.4 관리자 뉴스 편집

편집 가능한 대상은 `sourceType = manual`인 수동 기사뿐이다.

1. 수동 기사 상세 열기
2. 아래의 `편집` 선택
3. 기존 카테고리, 고정 여부, 제목, 내용, 링크, 썸네일 확인
4. 필요한 값 수정
5. 저장

자동 수집 기사는 관리자에게도 편집·삭제 버튼을 노출하지 않는다.

기존 썸네일은 다음 중 하나로 처리한다.

- 그대로 유지
- 다른 사진으로 교체
- 제거하고 기본 썸네일 사용

### 5.5 관리자 뉴스 삭제

뉴스 삭제는 현재 확인 창 없이 즉시 실행된다.

1. 수동 기사 상세 열기
2. `삭제` 선택
3. 즉시 서버 삭제
4. 뉴스 목록 갱신 후 상세 닫힘

삭제 버튼을 시험용으로 누르지 않는다. 삭제 전 제목과 대상 기사를 다시 확인한다.

### 5.6 뉴스 고정

- 작성·편집 화면에서 `최상단 고정`을 켠다.
- 고정 기사는 선택된 카테고리 피드의 일반 기사보다 먼저 표시한다.
- 고정 가능한 기사 수의 서버 상한은 100개다.
- 지나치게 많은 기사를 고정하면 고정의 의미가 없어지므로 운영 정책상 최소한만 유지한다.

### 5.7 뉴스 썸네일

#### 선택

- 앱 내부 커스텀 사진 그리드를 사용한다.
- 사진 접근 권한이 필요하다.
- 한 장만 선택할 수 있다.
- 원본 크기는 최대 10MB다.

#### 서버 처리

- 실제 파일 바이트가 JPEG, PNG, WebP, GIF인지 확인한다.
- 확장자만 바꾼 파일은 거부한다.
- 서버에서 240×240 JPEG, 품질 80으로 변환한다.
- 뉴스 썸네일 버킷은 공개 URL을 사용한다.

#### 기본 썸네일

- 관리자가 썸네일을 선택하지 않은 기사
- 자동 수집 중 썸네일 수집에 실패한 기사
- 외부 썸네일이 없는 기사

위 경우에는 머니로드 기본 썸네일을 표시한다. 자동 수집 기사는 썸네일 실패 때문에 기사 전체를 버리지 않는다.

### 5.8 뉴스 운영 점검

매일 확인:

- 전체·카테고리 탭에 새 기사가 표시되는지
- 고정 기사가 각 카테고리 상단에 있는지
- `머니로드 독점`과 `머니로드 요약` 표시가 맞는지
- 썸네일 없는 기사에 기본 이미지가 표시되는지
- 원문 링크가 실제 기사로 열리는지
- 연결 종목이 올바른지

썸네일 업로드가 모두 실패할 때:

1. 서버의 `NEWS_THUMBNAIL_BUCKET` 확인
2. 서버 서비스 계정의 버킷 쓰기 권한 확인
3. 이미지 형식과 10MB 제한 확인
4. 서버 이미지 변환 로그 확인

## 6. 시그널 운영

### 6.1 사용자 시그널 화면

- 홈에는 공개 시그널 미리보기만 표시한다.
- 시그널 전체 탭은 로그인이 필요하다.
- 시그널 카드는 종목, 매수·매도·관망, 강도, 제목, 설명, 근거를 표시한다.
- 시그널 피드는 생성·삭제 이벤트를 SSE로 받아 갱신한다.

### 6.2 관리자 시그널 작성

진입:

1. 관리자 계정으로 로그인
2. `시그널` 탭 이동
3. 새 시그널 작성 버튼 선택

입력 항목:

| 항목 | 필수 | 제한 |
|---|---:|---|
| 종목 | 필수 | 종목 검색에서 실제 종목 선택 |
| 행동 | 필수 | 매수, 매도, 관망 |
| 강도 | 필수 | 1~5, 기본값 3 |
| 제목 | 필수 | 최대 80자 |
| 설명 | 필수 | 최대 500자 |

수동 관리자 시그널의 내부 출처는 현재 `community`로 저장된다. 이것은 자동 커뮤니티 시그널 엔진이 구현됐다는 뜻이 아니라 수동 생성 데이터의 저장 구분값이다.

저장 성공 후:

- 시그널 피드 갱신
- 시그널 개수 갱신
- 조건에 맞는 사용자를 대상으로 푸시 전송 시도

푸시 전송 실패가 시그널 생성 자체를 실패시키지는 않는다.

### 6.3 관리자 시그널 삭제

`시그널 관리` 목록의 삭제 버튼은 확인 창 없이 즉시 실행한다.

- 목록에서는 낙관적으로 즉시 사라진다.
- 서버 요청 완료 뒤 시그널 피드와 개수를 다시 갱신한다.
- 삭제 시 별도의 푸시는 보내지 않는다.

삭제 전 종목, 행동, 제목을 다시 확인한다.

### 6.4 시그널 푸시 대상

다음 조건을 모두 만족해야 한다.

1. 사용자가 해당 종목을 관심 종목으로 등록
2. 해당 행동 유형의 알림 설정이 켜짐
3. 유효한 기기 푸시 토큰 등록
4. 푸시 제공 환경에서 실행
5. 동일 사용자·알림 유형의 5분 쿨다운에 걸리지 않음

기본 알림 설정:

| 유형 | 기본값 |
|---|---:|
| 매수 시그널 | 켜짐 |
| 매도 시그널 | 켜짐 |
| 관망 시그널 | 꺼짐 |

### 6.5 푸시 확인 방법

- 에뮬레이터만으로 최종 푸시 수신을 판정하지 않는다.
- 실제 기기와 개발 빌드에서 테스트한다.
- OS 알림 권한을 허용했는지 확인한다.
- 테스트 계정이 대상 종목을 관심 종목으로 등록했는지 확인한다.
- 마이페이지에서 해당 시그널 알림이 켜져 있는지 확인한다.
- 최근 5분 안에 같은 유형 알림을 이미 받았는지 확인한다.

### 6.6 현재 구현되지 않은 시그널 기능

- 가격 데이터를 자동 분석해 시그널을 자동 생성하는 운영 엔진
- AI 모델이 자동 생성하는 시그널 운영
- 이벤트 기반 자동 시그널 생성
- 커뮤니티 활동을 집계해 자동 생성하는 시그널
- 온보딩의 시그널 종류 선택값 저장
- 답글 작성에 대한 푸시 알림

현재 운영자가 사용할 수 있는 생성 방식은 관리자 수동 시그널 작성이다.

## 7. 토론방 목록 운영

### 7.1 토론방 탭

토론방 목록의 주요 구분:

- 인기
- 관심 종목
- 최신
- 즐겨찾기

비로그인 사용자는 인기·최신 목록을 볼 수 있다. 관심 종목, 즐겨찾기, 토론방 검색은 로그인해야 한다.

### 7.2 좋아요와 즐겨찾기

두 기능은 서로 다르다.

| 기능 | 표시 | 의미 |
|---|---|---|
| 좋아요 | 하트와 공개 개수 | 방에 대한 공개 반응 |
| 즐겨찾기 | 별, 개인 상태 | 사용자의 개인 보관 |

좋아요 하트는 제거 대상이 아니며 현재 유지한다. 두 동작 모두 로그인이 필요하다.

### 7.3 토론방 검색

- 로그인 후 이용한다.
- 선택된 탭과 관계없이 전체 방을 대상으로 검색한다.
- 토론방 이름과 연결 종목을 검색한다.
- 일부 문자열 검색과 공백 차이를 허용한다.

### 7.4 목록 갱신 방식

- 토론방 목록 변화는 SSE 이벤트로 알림을 받아 다시 조회한다.
- 메시지 본문 자체는 WebSocket이나 SSE로 전달하지 않는다.
- 메시지 목록은 현재 5초 폴링을 유지한다.

방 생성·편집·삭제, 메시지 전송·모더레이션, 좋아요 변경 뒤 목록 개수는 이벤트 또는 쿼리 무효화로 갱신된다.

## 8. 관리자 토론방 생성·편집·삭제

### 8.1 토론방 생성

관리자만 새 토론방을 만들 수 있다.

| 항목 | 필수 | 제한 |
|---|---:|---|
| 방 이름 | 필수 | 최대 50자 |
| 설명 | 필수 | 최대 200자 |
| 연결 종목 | 선택 | 실제 종목 검색에서 선택 |
| 분위기 | 필수 | 상승, 중립, 하락 |

종목을 연결하면 종목 상세의 관련 토론과 관심 종목 토론에서 방을 찾을 수 있다.

### 8.2 토론방 편집

- 관리자만 편집할 수 있다.
- 기존 값이 작성 화면에 채워진다.
- 수정 중 뒤로 가면 저장하지 않은 변경을 확인하는 경고를 표시한다.
- 방 카드의 편집 버튼은 방 이름과 설명 레이아웃에 영향을 주지 않는 별도 조작 영역이다.

### 8.3 토론방 삭제

토론방 삭제는 확인 창 없이 즉시 실행되는 영구 삭제다.

함께 삭제되는 데이터:

- 방 메시지와 답글
- 방 회원 정보
- 좋아요
- 즐겨찾기
- 가림·차단 등 방 종속 데이터

복구 기능이 없으므로 삭제 전 방 이름과 연결 종목을 반드시 재확인한다.

## 9. 토론 메시지·답글

### 9.1 메시지 종류

텍스트, 이미지, 파일은 모두 동일한 `Message` 단위로 취급하며 `type`으로 구분한다.

| 유형 | `type` | 구성 |
|---|---|---|
| 텍스트 | `text` | 본문 |
| 이미지 | `image` | 이미지 1~8장 |
| 파일 | `file` | 파일 1개 |

한 메시지 안에 이미지와 파일을 섞지 않는다.

### 9.2 텍스트 메시지

- 로그인 회원만 작성할 수 있다.
- 본문 최대 1,000자다.
- 전송 후 메시지 목록과 방 목록 개수를 갱신한다.
- 다른 사용자의 새 메시지는 최대 약 5초 뒤 표시될 수 있다.

### 9.3 답글 작성

1. 삭제·가림되지 않은 메시지를 길게 누른다.
2. `답글` 선택
3. 입력창 위의 인용 미리보기 확인
4. 내용 입력
5. 전송

관리자는 길게 누른 메뉴에 `답글`, `숨김`, `삭제`가 표시된다. 일반 회원은 `답글`만 표시된다.

답글에 다시 답글을 달면 사용자가 직접 길게 누른 바로 그 메시지를 부모로 저장한다.

### 9.4 인용과 이동

- 답글 말풍선 위에 원문 인용을 표시한다.
- 인용 영역을 누르면 원문 위치로 이동한다.
- `내가 쓴 글·답글`에서 항목을 누르면 해당 토론방의 메시지 위치로 이동한다.
- 과거 메시지로 이동한 동안은 화면 위치가 튀지 않도록 일반 폴링을 잠시 멈추고 주변 메시지를 불러온다.
- 최신 끝까지 이동하면 일반 5초 폴링으로 돌아간다.

### 9.5 내가 쓴 글·답글

`마이 > 내가 쓴 글·답글`에서 다음처럼 구분한다.

- 글: 부모 메시지가 없는 내가 작성한 메시지
- 답글: 부모 메시지가 있는 내가 작성한 메시지

텍스트가 아닌 메시지는 다음처럼 표시한다.

- 이미지: `사진`
- 파일: `파일 · 파일명`

목록에는 직접 답글 개수, 토론방 이름, 연결 종목, 작성일을 표시한다.

### 9.6 일반 회원의 삭제 제한

현재 앱 UI에서 일반 회원은 본인이 작성한 메시지도 직접 삭제하지 못한다. 삭제는 관리자 모더레이션 기능으로만 제공한다.

## 10. 관리자 메시지 가림·삭제

### 10.1 공통 진입

1. 관리자 계정으로 토론방 입장
2. 삭제·가림되지 않은 메시지를 길게 누름
3. `숨김` 또는 `삭제` 선택
4. 메시지 선택 모드 진입
5. 한 개 이상 선택
6. 화면 아래 `숨김 (N)` 또는 `삭제 (N)` 실행

처음 길게 누른 메시지는 선택된 상태로 시작한다. 선택 개수가 0이면 실행 버튼은 동작하지 않는다.

### 10.2 가림

1. `숨김 (N)` 선택
2. 가림 사유 하나 선택
3. `저장` 선택

가림 사유는 다음 7개로 고정한다.

1. 혐오/차별적/생명경시/욕설 표현입니다
2. 스팸홍보/도배입니다
3. 음란물입니다
4. 불법정보를 포함하고 있습니다
5. 청소년에게 유해한 내용입니다
6. 개인정보가 노출되었습니다
7. 불쾌한 표현이 있습니다

가림 후:

- 원문과 첨부를 사용자 응답에서 숨긴다.
- 말풍선에는 `이 메시지는 '선택 사유' 사유로 가림 처리되었습니다.`를 표시한다.
- DB에는 원문, 처리 시각, 처리 관리자, 사유를 감사 목적으로 보존한다.
- 가림된 메시지에는 새 답글을 달 수 없다.
- 해당 메시지를 인용한 기존 답글에는 `가려진 글입니다`만 표시한다.

서버에는 관리자 복원 API가 있지만 현재 앱 운영 메뉴에는 가림 해제 버튼이 없다. 복원이 필요하면 승인된 유지보수 절차로 처리한다.

### 10.3 삭제

1. `삭제 (N)` 선택
2. 별도 사유 선택 없이 즉시 처리

삭제 후:

- 원문과 첨부를 사용자 응답에서 숨긴다.
- 삭제된 메시지 자리에는 `삭제된 메시지입니다`를 표시한다.
- 기존 답글은 유지한다.
- 기존 답글의 인용에는 `삭제된 글입니다`를 표시한다.
- 삭제된 메시지에는 새 답글을 달 수 없다.
- DB 행은 답글 관계 보존을 위해 소프트 삭제한다.

토론방 자체 삭제와 메시지 삭제를 혼동하지 않는다. 방 삭제는 방 전체 영구 삭제이고, 메시지 삭제는 답글 구조를 보존하는 소프트 삭제다.

### 10.4 모더레이션 기록 권장사항

앱 안에 별도의 운영 기록 다운로드 화면은 없다. 민감한 대량 처리 전후에는 내부 운영 정책에 따라 다음을 별도로 기록한다.

- 토론방
- 처리 관리자
- 처리 시각
- 대상 메시지 수
- 가림 사유 또는 삭제 근거
- 관련 신고 번호

## 11. 토론방 회원 관리

### 11.1 회원 목록

관리자만 토론방 상단의 햄버거 버튼으로 회원 목록을 열 수 있다.

- 현재·기존 참여 회원 목록
- 차단 회원 목록
- 회원별 음소거·차단 상태

관리자는 자신을 제재할 수 없고 다른 관리자도 음소거·차단할 수 없다.

### 11.2 음소거

음소거된 사용자는:

- 방 입장 가능
- 기존 메시지 읽기 가능
- 텍스트 전송 불가
- 이미지 전송 불가
- 파일 전송 불가

설정 절차:

1. 회원을 길게 누름
2. `mute` 선택
3. 정수 입력
4. 시간 또는 일 단위 선택
5. 저장

허용 범위:

- 시간 단위: 1~24시간
- 일 단위: 1일

기간이 지나면 자동 해제된다. 관리자는 만료 전 수동 해제할 수 있다.

### 11.3 차단

차단된 사용자는:

- 즉시 방 회원 목록에서 퇴출
- 차단 기간 동안 방 입장 불가
- 차단 기간 동안 메시지·이미지·파일 전송 불가
- 토론방 목록에서 방 카드 자체는 볼 수 있음

설정 절차:

1. 회원을 길게 누름
2. `차단하기` 선택
3. 시간 또는 일 단위와 기간 입력
4. 확인 문구에서 대상 사용자 재확인
5. 최종 확인

차단 기간은 최대 7일이다. 기간 만료 뒤에는 다시 입장할 수 있으며 관리자는 차단 목록에서 수동 해제할 수 있다.

영구 계정 차단 기능이 아니다. 다른 계정으로 접속하는 것까지 막는 장치도 아니다.

### 11.4 방 나가기

- 상단 `X`는 명시적 방 나가기다.
- 확인 창을 거친다.
- 방 회원 레코드에서 제거된다.
- 차단 상태가 아니라면 나중에 다시 메시지를 작성할 때 암묵적으로 방 회원이 될 수 있다.

## 12. 이미지 첨부

### 12.1 이미지 보내기

1. 토론방 입력창 왼쪽 `+` 선택
2. `파일` 메뉴 선택
3. `앨범에서 선택` 선택
4. 사진 접근 권한 허용
5. 앱 내부 최근 사진 그리드에서 선택
6. `완료`
7. 업로드 완료 확인

시스템 갤러리 앱 화면을 그대로 여는 방식이 아니다. 앱이 사진 보관함 접근 권한을 받아 최근 사진 메타데이터를 조회하고 머니로드 내부 커스텀 그리드로 표시한다.

### 12.2 선택 제한

- 최근 사진 후보 최대 120개
- 선택 최대 8장
- 원본 파일 합계 최대 10MB
- 선택 순서 배지 표시
- 선택 화면은 4열 그리드

8장을 모두 선택할 수 있더라도 합계가 10MB를 넘으면 전송할 수 없다.

### 12.3 허용 이미지

- JPEG
- PNG
- WebP
- GIF

파일 확장자나 MIME 문자열만 믿지 않고 실제 파일 바이트를 확인한다. HEIC·HEIF가 기기 목록에 표시되더라도 서버 허용 형식으로 판정되지 않으면 업로드가 실패할 수 있다.

서버 이미지 안전 제한:

- 한 변 최대 8,192px
- 전체 픽셀 최대 25,000,000
- EXIF 제거를 포함한 재인코딩

### 12.4 이미지 말풍선

여러 장은 한 이미지 메시지의 그리드로 표시한다.

| 장수 | 배치 |
|---:|---|
| 1 | 1장 전체 |
| 2 | 2장 |
| 3 | 3장 |
| 4 | 2×2 |
| 5 | 3장 + 2장 |
| 6 | 3장 + 3장 |
| 7 | 3장 + 3장 + 1장 |
| 8 | 3장 + 3장 + 2장 |

말풍선 그리드는 최대 3열이다.

### 12.5 부분 업로드 실패

예: 5장 중 3장 성공, 2장 실패

1. 성공한 3장은 하나의 이미지 메시지로 즉시 전송
2. 실패한 2장 개수 안내
3. `재시도` 또는 `취소` 선택
4. 재시도 성공분은 별도의 새 이미지 메시지로 전송

모두 실패하면 메시지를 만들지 않는다.

### 12.6 이미지 보기와 저장

- 말풍선 이미지를 누르면 전체 화면 뷰어가 열린다.
- 여러 장은 좌우로 넘겨 볼 수 있다.
- 우측 상단 메뉴에서 `갤러리에 저장`을 선택할 수 있다.
- 가능하면 `moneyroad` 앨범에 저장한다.
- OS 권한 범위 때문에 앨범 지정이 불가능하면 사진 보관함에 저장하고 실제 저장 위치 문구를 표시한다.

## 13. 파일 첨부·열기·저장

### 13.1 파일 보내기

1. 토론방 입력창 왼쪽 `+` 선택
2. `파일` 메뉴 선택
3. `파일에서 선택` 선택
4. Android는 시스템 Storage Access Framework, iOS는 문서 브라우저 표시
5. 파일 1개 선택
6. 업로드·전송 완료 확인

특정 저장 경로를 코드에 하드코딩하지 않는다. Android에서 `내 파일`과 비슷한 최근 파일 화면이 보이는 것은 시스템 문서 선택기가 제공하는 화면이다.

광범위 저장소 읽기 권한을 요구하지 않고 사용자가 선택한 파일 URI에 대해서만 접근한다.

### 13.2 파일 제한

- 메시지 하나당 파일 1개
- 파일 하나당 최대 20MB

허용 확장자:

- 문서: `pdf`, `txt`, `md`
- 워드: `doc`, `docx`
- 스프레드시트: `xls`, `xlsx`
- 프레젠테이션: `ppt`, `pptx`
- 한글: `hwp`, `hwpx`
- 이미지 파일: `jpg`, `jpeg`, `png`, `gif`, `webp`

허용 확장자로 이름만 바꾼 실행 파일은 실제 바이트 검사에서 거부한다.

### 13.3 파일 열기

- 파일 이름을 누르면 먼저 저장된 로컬 파일이 있는지 확인한다.
- 저장본이 없으면 앱 캐시에 내려받아 설치된 앱으로 연다.
- 캐시로 연 것은 영구 저장으로 표시하지 않는다.
- 기기에 해당 형식을 열 앱이 없으면 `저장하기`를 안내한다.
- 첨부 바이트는 로그인 세션을 실은 서버 프록시로만 내려받는다.
- 외부 앱에는 로컬 파일 URI만 전달한다.

### 13.4 파일 저장

Android:

1. 처음 저장할 때 저장 폴더 선택 안내 표시
2. 시스템 폴더 선택기에서 기준 폴더 선택
3. 선택 폴더 아래 `moneyroad/file` 생성
4. 선택 권한과 실제 저장 폴더 URI를 안전 저장소에 보관
5. 다음 저장부터 같은 폴더 사용

iOS:

- 앱 문서함 아래 `moneyroad/file`에 저장
- 파일 앱에서 앱 문서 영역을 통해 접근

저장 경로 권한이 회수되거나 폴더가 삭제되면 다음 저장에서 다시 폴더를 선택해야 할 수 있다.

### 13.5 첨부 보안

- 토론 첨부 버킷은 비공개다.
- 앱에 원본 버킷 주소나 장기 서명 URL을 노출하지 않는다.
- 방 접근 권한을 서버에서 확인한 뒤 이미지·파일 프록시를 제공한다.
- 가림·삭제된 메시지의 첨부는 내려받을 수 없다.
- 파일명은 경로 탈출 문자를 제거한 안전한 이름으로 저장한다.

첨부 기능이 전체적으로 503 오류를 반환하면 서버의 `DISCUSSION_ATTACHMENT_BUCKET` 설정을 먼저 확인한다.

## 14. 알림함·알림 설정·가격 알림

### 14.1 알림함

`마이 > 알림함`에서 다음을 제공한다.

- 전송된 알림 이력
- 읽지 않은 알림 수
- 개별 읽음 처리
- 전체 읽음 처리

알림 이력은 실제 전송 상태가 성공으로 기록된 항목을 기준으로 한다.

### 14.2 시그널 알림 설정

`마이 > 시그널 알림 설정`

- 매수 시그널
- 매도 시그널
- 관망 시그널

토글 변경은 서버의 사용자 알림 설정에 저장된다.

### 14.3 뉴스·공시 알림 설정

`마이 > 뉴스·공시 알림 설정`

- 관심 종목 뉴스·공시 알림 켜기·끄기
- 기본값 켜짐

현재 알림 대상은 사용자가 관심 종목으로 등록한 종목의 뉴스·공시다.

### 14.4 가격 알림 생성

접근 경로:

- 종목 상세의 알림 버튼
- `마이 > 가격 알림 > 추가`

설정 항목:

- 종목
- 현재가 이상 도달 또는 이하 도달
- 양수 정수 목표가
- 현재가 기준 빠른 선택값 또는 직접 입력

### 14.5 가격 알림 동작

- 목표가에 처음 도달할 때 1회 푸시
- 한 번 발동한 알림은 자동 반복하지 않음
- 다시 활성화하면 발동 시각을 초기화하고 다시 감시
- 장 운영 시간 외에는 알림이 지연될 수 있음
- 목록에서 활성화·비활성화 가능
- 삭제 버튼은 별도 확인 없이 즉시 삭제

가격 알림이 오지 않을 때:

1. 알림이 활성 상태인지 확인
2. 이미 한 번 발동한 알림인지 확인
3. OS 푸시 권한과 기기 토큰 확인
4. 현재가가 선택한 방향으로 실제 도달했는지 확인
5. 실시간 가격 수신과 가격 알림 작업 로그 확인

## 15. 공지사항·고객 지원·문의

### 15.1 공지사항

일반 사용자는 `마이 > 공지사항 및 고객 지원`에서 공지 목록과 상세를 볼 수 있다.

공지 카테고리:

- 공지
- 업데이트
- 이벤트

고정 공지는 목록 상단에 표시한다.

### 15.2 관리자 공지 작성

1. 관리자 계정으로 `공지사항 및 고객 지원` 진입
2. 새 공지 작성
3. 카테고리 선택
4. 제목과 본문 입력
5. 필요하면 최상단 고정
6. 저장

제한:

| 항목 | 제한 |
|---|---:|
| 제목 | 최대 100자 |
| 본문 | 최대 2,000자 |

### 15.3 관리자 공지 고정·삭제

공지 상세에서 관리자는 다음을 실행할 수 있다.

- 최상단 고정
- 고정 해제
- 삭제

공지 삭제도 현재 별도 확인 창 없이 즉시 실행한다. 공지 편집 기능은 현재 제공하지 않으므로 내용이 잘못되면 삭제 후 다시 작성한다.

### 15.4 1:1 문의

1:1 문의는 로그인이 필요하며 DB에 저장된다.

문의 유형:

- 시그널
- 구독
- 계정
- 기타

입력 제한:

| 항목 | 제한 |
|---|---:|
| 제목 | 1~100자 |
| 내용 | 1~2,000자 |
| 연락 이메일 | 올바른 이메일 형식 |

연락 이메일을 따로 입력하지 않으면 로그인 계정 이메일을 사용한다. 접수 완료 뒤 사용자는 등록 이메일로 답변받는다는 안내를 본다.

문의 운영 시간 안내는 평일 09:00~18:00이며, 일반 지원 이메일은 `support@moneyroad.ai.kr`이다.

현재 앱 안에는 운영자용 문의 답변·상태 변경 화면이 없다. 접수 DB 또는 별도 승인된 고객 지원 도구에서 처리해야 한다.

### 15.5 약관과 개인정보 처리방침

`마이 > 공지사항 및 고객 지원`에서 다음 문서를 연다.

- 이용약관
- 개인정보 처리방침

배포 전 실제 회사 정책, 시행일, 연락처와 일치하는지 법무·개인정보 담당자가 검수해야 한다.

## 16. 머니게이트 회사 사이트 운영

### 16.1 사이트 성격

- 머니게이트 회사 소개 사이트
- 로그인 없는 공개 사이트
- Next.js 기반 정적 콘텐츠 중심 사이트
- 별도의 관리자 CMS가 없음
- 콘텐츠 변경은 코드 수정, 검증, 빌드, 배포가 필요

### 16.2 공개 경로

| 경로 | 내용 |
|---|---|
| `/` | 메인 |
| `/company` | 회사소개 |
| `/service` | 사업·서비스 |
| `/notice` | 공지사항 |
| `/disclosure` | 법적 고지·공시 |
| `/faq` | FAQ |
| `/contact` | 문의 |
| `/service/moneyroad` | `https://moneyroad.ai.kr/`로 리다이렉트 |

머니로드는 별도의 앱 소개 사이트다. 회사 사이트 안에 중복 앱 소개 페이지를 운영하지 않고 머니로드 메뉴와 버튼은 `moneyroad.ai.kr`로 연결한다.

### 16.3 사이트 콘텐츠 수정 위치

공통 콘텐츠는 다음 파일을 우선 확인한다.

`apps/company/src/app/content.ts`

주요 데이터:

- `navigation`: 상단·하단 메뉴
- `businessAreas`: 사업·서비스 상세
- `homeBusinessAreas`: 메인 사업 영역
- `serviceFeatures`: 머니로드 기능
- `processSteps`: 정보 수집·검증·제공 흐름
- `principles`: 운영 원칙
- `history`: 회사 연혁
- `team`: 조직·사람
- `companyFacts`: 대표자·법인 정보·주소 등
- `notices`: 회사 사이트 공지
- `disclosures`: 법적 고지·공시
- `faqs`: FAQ
- `contactTypes`: 문의 유형

페이지 구조와 표현을 변경할 때는 각 경로의 `page.tsx`와 공통 컴포넌트, `globals.css`를 함께 확인한다.

### 16.4 정적 콘텐츠 운영 절차

1. 수정 대상과 근거 자료 확인
2. `content.ts`의 해당 데이터 수정
3. 날짜, 링크, 연락처, 회사 정보 재검증
4. 로컬에서 모든 경로 확인
5. PC·태블릿·모바일 폭 확인
6. 타입 검사
7. 프로덕션 빌드
8. 승인 후 배포
9. 실제 도메인에서 다시 확인

### 16.5 배포 전 반드시 교체할 예시 데이터

현재 설계·미리보기를 위해 예시값이 포함될 수 있다.

- 대표자명
- 설립일
- 사업자등록번호
- 통신판매업 신고번호
- 주소
- 대표 전화
- 대표 이메일
- 개인정보 전담 이메일
- 연혁의 날짜와 사건
- 팀 이름·직책·인물
- 공지 날짜와 본문
- 공시·법적 고지 내용

예시값을 실제 회사 정보처럼 배포하면 안 된다. 회사 내부 승인 자료와 대조한 뒤 교체한다.

### 16.6 연락처 운영

사이트에 표시되는 전화·이메일은 실제 응대 가능한 채널인지 확인한다.

- 대표 전화
- 서비스·일반 문의 이메일
- 개인정보 보호 전담 이메일

변경 시 다음 위치를 모두 점검한다.

- 문의 페이지 카드
- 푸터 회사 정보
- 개인정보 처리방침
- FAQ
- 메일 링크

### 16.7 공지·공시 운영

회사 사이트의 공지와 공시는 현재 DB 관리 화면이 아니라 `content.ts` 정적 데이터다.

게시 절차:

1. 제목, 분류, 날짜, 본문, 링크 확정
2. 법무·운영 승인
3. 정적 데이터 추가
4. 목록 정렬과 상세 링크 확인
5. 빌드·배포

앱 안의 공지사항 DB와 회사 사이트의 정적 공지는 서로 다른 기능이다. 한쪽에 등록했다고 다른 쪽에 자동 반영되지 않는다.

### 16.8 디자인 운영 기준

- 기본 폰트: Wanted Sans Variable
- 숫자·작은 영문 라벨: Geist Mono
- 어두운 남색·검정 배경과 머니게이트 파란색 강조
- 스크롤 진입 시 아래에서 올라오는 Reveal 효과
- `prefers-reduced-motion` 환경에서는 불필요한 애니메이션을 줄임
- 모바일에서 제목이 잘리거나 가로 스크롤이 생기지 않아야 함

기관 로고는 승인된 실제 로고 파일과 사용 조건을 확인한 뒤 사용한다. 텍스트 약어를 실제 기관 로고처럼 오인하게 표시하지 않는다.

### 16.9 회사 사이트 검증 명령

저장소 루트에서:

```bash
pnpm --filter company check-types
pnpm --filter company build
```

전체 통합 검증:

```bash
pnpm check
pnpm check-types
pnpm build
```

로컬 실행:

```bash
pnpm --filter company dev
```

회사 앱 기본 개발 포트는 5002다. 운영 도메인의 캐시나 CDN 때문에 변경이 늦게 보일 수 있으므로 로컬 빌드와 실제 배포본을 구분한다.

## 17. 실시간 서비스 운영

### 17.1 실시간으로 처리되는 영역

- 실시간 주가
- 종목 차트 프록시
- 뉴스 피드 갱신 이벤트
- 시그널 피드 갱신 이벤트
- 토론방 목록 갱신 이벤트
- 종목 마스터 갱신
- 푸시 알림 작업

### 17.2 토론의 실시간 범위

| 대상 | 현재 방식 |
|---|---|
| 토론방 목록 갱신 신호 | SSE |
| 방 상세 메타 | 5초 폴링 |
| 메시지 목록 | 5초 폴링 |
| 메시지 전송 | API 요청 후 다시 조회 |
| 메시지 WebSocket | 미구현 |
| 메시지 SSE 본문 전송 | 미구현 |

메시지가 즉시 보이지 않고 최대 약 5초 뒤 보이는 것은 현재 구조에서 정상 범위다.

### 17.3 실시간 서비스 인스턴스

현재 뉴스·시그널·토론 SSE 허브와 KIS 연결 상태가 프로세스 메모리에 있다. Redis나 별도 Pub/Sub으로 상태를 옮기기 전에는 실시간 Cloud Run 인스턴스를 임의로 여러 개로 늘리지 않는다.

권장 현재 설정:

- 최소 인스턴스 1
- 최대 인스턴스 1

여러 인스턴스로 늘리면 클라이언트가 연결된 인스턴스와 갱신 이벤트를 받은 인스턴스가 달라져 일부 SSE 갱신을 놓칠 수 있다.

### 17.4 공통 비밀값

API 서버와 실시간 서비스의 `STREAM_TOKEN_SECRET`은 동일해야 하며 최소 32자 이상의 안전한 값으로 관리한다. 로그, 문서, 앱 번들에 실제 값을 남기지 않는다.

내부 갱신 엔드포인트와 비밀값을 공개 API처럼 외부에 노출하지 않는다.

## 18. 저장소·환경 변수 운영

### 18.1 주요 서버 환경 변수

| 변수 | 목적 |
|---|---|
| `DATABASE_URL` | PostgreSQL 연결 |
| `BETTER_AUTH_SECRET` | 인증 서명 비밀값 |
| `BETTER_AUTH_URL` | 인증 기준 URL |
| `CORS_ORIGIN` | 허용 앱·웹 출처 |
| `STREAM_TOKEN_SECRET` | API·실시간 서비스 공통 스트림 토큰 |
| `DISCUSSION_ATTACHMENT_BUCKET` | 비공개 토론 첨부 버킷 |
| `NEWS_THUMBNAIL_BUCKET` | 공개 뉴스 썸네일 버킷 |
| `REALTIME_INTERNAL_URL` | API에서 실시간 내부 갱신 호출 |

OAuth 관련 키는 해당 로그인 제공자를 실제로 활성화할 때만 운영 비밀 저장소에 설정한다.

### 18.2 토론 첨부 버킷

- 비공개
- 서버 서비스 계정에 필요한 객체 쓰기·읽기 권한
- 앱은 서버 프록시를 통해서만 접근
- 버킷 미설정 시 토론 첨부 업로드 비활성

### 18.3 뉴스 썸네일 버킷

- 공개 이미지 제공 목적
- 서버·수집 서비스에서 동일한 버킷 설정 확인
- 브라우저·앱에서 접근 가능한 공개 URL 생성
- 개인정보나 비공개 이미지를 뉴스 썸네일 버킷에 올리지 않음

### 18.4 DB 마이그레이션

- 스키마 변경 뒤 프로젝트의 생성·마이그레이션 명령을 사용한다.
- 생성된 마이그레이션 SQL을 임의로 손편집하지 않는다.
- 로컬 데이터가 필요 없는 개발 환경은 승인된 절차로 DB 초기화 후 전체 마이그레이션을 적용할 수 있다.
- 운영 DB 초기화는 이 문서의 범위를 벗어나며 절대 개발 환경과 같은 방식으로 실행하면 안 된다.

### 18.5 Expo 네이티브 패키지

현재 첨부 관련 패키지:

- `expo-document-picker`
- `expo-file-system`
- `expo-image`
- `expo-media-library`
- 플랫폼별 파일 열기를 위한 관련 Expo 모듈

Expo 라이브러리를 추가·수정할 때는 SDK 호환 버전을 설치하기 위해 다음 형식을 사용한다.

```bash
pnpm expo install <라이브러리명>
```

일반 `pnpm add`로 Expo SDK 연동 패키지 버전을 임의 선택하지 않는다. 네이티브 의존성이 바뀌면 개발 빌드를 다시 만든다.

## 20. 장애 대응

### 20.1 앱 전체에서 데이터가 안 보임

1. API 상태 확인
2. DB 연결 확인
3. 인증 세션 오류 여부 확인
4. 앱의 API URL 환경 변수 확인
5. 최근 배포 로그 확인

### 20.2 시세·차트만 안 보임

1. 실시간 서비스 상태
2. KIS 연결 상태
3. 종목 마스터 존재 여부
4. 스트림 토큰 비밀값 일치
5. 장 운영 시간과 데이터 제공 시간

### 20.3 뉴스·시그널·토론 목록이 자동 갱신되지 않음

1. 실시간 서비스 SSE 연결 확인
2. API에서 내부 갱신 요청이 성공하는지 확인
3. `REALTIME_INTERNAL_URL` 확인
4. `STREAM_TOKEN_SECRET` 일치 확인
5. 실시간 서비스 인스턴스가 1개인지 확인
6. 앱을 새로 열었을 때 수동 조회 결과가 맞는지 확인

수동 재조회는 되지만 자동 갱신만 안 되면 SSE 또는 내부 갱신 경로 문제일 가능성이 높다.

### 20.4 토론 메시지가 늦게 보임

- 메시지는 SSE가 아니라 5초 폴링이다.
- 5초 이내 지연은 정상일 수 있다.
- 5초 이상 계속 갱신되지 않으면 메시지 API와 앱 포그라운드 상태를 확인한다.

### 20.5 사진 권한이 거부됨

1. 앱 내부 안내에서 `설정 열기`
2. OS 앱 권한에서 사진 접근 허용
3. 선택된 사진만 허용한 경우 필요한 사진이 허용 범위에 있는지 확인
4. 앱으로 돌아와 다시 시도

파일 선택에는 사진 보관함 권한이 필요하지 않다.

### 20.6 이미지·파일 업로드 실패

1. 사용자 로그인과 방 차단·음소거 상태 확인
2. 이미지 합계 10MB 또는 파일 20MB 제한 확인
3. 허용 형식 확인
4. 이미지 해상도 제한 확인
5. 첨부 버킷 환경 변수 확인
6. 서비스 계정 버킷 권한 확인
7. 서버 업로드 로그 확인

### 20.7 파일을 열 수 없음

- 해당 파일 형식을 열 수 있는 앱이 기기에 설치됐는지 확인
- `저장하기`로 저장한 뒤 파일 관리자에서 다른 앱으로 열어 본다
- 가림·삭제된 메시지인지 확인
- 로그인 세션이 만료됐는지 확인

### 20.8 푸시가 오지 않음

1. 실제 기기인지 확인
2. 개발 빌드인지 확인
3. OS 알림 권한 확인
4. 푸시 토큰 등록 확인
5. 관심 종목 등록 확인
6. 해당 알림 유형 설정 확인
7. 5분 쿨다운 확인
8. 푸시 작업 로그와 전송 결과 확인

### 20.9 차단·음소거가 적용되지 않음

1. 대상이 일반 회원인지 확인
2. 대상이 본인 또는 다른 관리자인지 확인
3. 기간 입력이 허용 범위인지 확인
4. 서버 시간이 올바른지 확인
5. 해당 방과 사용자가 맞는지 확인
6. 제재 API와 DB 상태 확인

### 20.10 온보딩이 반복됨

1. RFC 0009 변경이 실제 배포 브랜치에 병합됐는지 확인
2. 계정의 `onboardingCompletedAt` 저장 여부 확인
3. 관심 종목 저장과 완료 처리가 함께 성공했는지 확인
4. 최신 DB 마이그레이션 적용 여부 확인
5. 신규 계정과 기존 계정을 구분해 재현

### 20.11 회사 사이트 변경이 보이지 않음

1. 수정한 브랜치와 배포 브랜치 일치 확인
2. `company` 타입 검사와 빌드 확인
3. 배포 완료 여부 확인
4. 실제 도메인 연결 대상 확인
5. CDN·브라우저 캐시 무효화 또는 새로고침
6. 정적 콘텐츠를 앱 공지 DB에만 수정한 것은 아닌지 확인

## 21. 현재 운영 대상에서 제외하는 기능

다음 항목은 UI가 보이거나 코드에 화면이 있어도 현재 실제 운영 기능이 아니다.

### 21.1 준비 중 화면

- AI 시그널 학습 데이터
- 화면 표시 설정
- 공유 및 친구 초대

이 화면들은 `준비 중이에요` 안내를 띄운다. 내부 화면 코드에 임시 로컬 값이나 예시 숫자가 있어도 DB 저장이나 실제 보상·개인화 처리로 연결되지 않는다.

### 21.2 아직 구현하지 않는 기능

- 온보딩 시그널 종류 선택값 반영
- 기술·AI 모델·이벤트·커뮤니티 자동 시그널 엔진
- 검색 화면과 서버 종목 마스터 통합
- 사용자별 최근 검색 저장·삭제
- 실제 검색량 기반 실시간 인기 종목
- 메시지 WebSocket 전송
- 메시지 SSE 본문 스트리밍
- 일반 회원의 본인 메시지 삭제
- 토론 답글 푸시
- 관리자용 1:1 문의 답변 화면
- 회사 사이트 CMS
- 회사 사이트 공지와 앱 공지의 자동 동기화
- 관리자 메시지 가림 해제 UI

운영자가 위 기능을 이미 제공되는 기능으로 안내하지 않도록 한다.

### 21.3 제품 기능이 아닌 템플릿 코드

저장소에 남아 있는 Todo, drawer 예제, waitlist 예제 등은 머니로드 운영 기능으로 간주하지 않는다. 실제 머니로드 라우트와 승인된 RFC에 연결된 화면만 운영 대상이다.

## 25. 변경 관리 원칙

- 기능을 바꾸면 코드와 RFC를 먼저 맞춘 뒤 이 매뉴얼을 같은 변경에서 갱신한다.
- 팀장님이 작성한 기존 설계 원칙은 임의로 변경하지 않는다.
- 구현과 문서가 다르면 추측으로 운영하지 말고 실제 화면·API·DB 동작을 확인한다.
- 관리자 삭제처럼 복구할 수 없는 동작은 새 확인 절차를 임의로 만들기 전에 RFC와 팀 지침을 먼저 갱신한다.
- 재사용 가능한 기존 화면·컴포넌트·서버 권한 검사를 우선 사용한다.
- 준비 중 기능을 운영 가능 기능처럼 문서화하거나 고객에게 안내하지 않는다.
- 환경 변수, 비밀키, 실제 사용자 개인정보를 이 문서나 Git에 기록하지 않는다.
